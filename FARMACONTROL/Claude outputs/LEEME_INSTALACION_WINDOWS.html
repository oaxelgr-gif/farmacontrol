FarmaControl · Instalación en Windows 10

Esta computadora será el servidor: los demás equipos de la red (doctores, farmacéuticos, celulares) entran desde su navegador.

Qué trae esta instalación: 1 usuario administrador (admin / 131004131004), 3 productos de prueba (código de barras 0000000000001, …02 antibiótico, …03) y 2 pacientes de prueba (PACIENTE PRUEBA UNO y DOS). Todo lo demás (anaqueles base, métodos de pago, servicios y consultas del catálogo) viene igual que siempre.

Windows 10 ya terminó su soporte general de Microsoft. Docker Desktop puede seguir funcionando, pero conviene tener la PC con todas las actualizaciones (y, si se puede, migrar a Windows 11 más adelante).

1Instalar WSL 2 (base que usa Docker)

Abre PowerShell como administrador (clic derecho en Inicio → «Windows PowerShell (Administrador)») y ejecuta:

wsl --install --no-distribution
wsl --update
wsl --set-default-version 2

Si --no-distribution marca error, usa solo wsl --install. Reinicia la computadora al terminar.

2Instalar Docker Desktop

Otra vez en PowerShell como administrador:

winget install -e --id Docker.DockerDesktop --accept-package-agreements --accept-source-agreements

Si winget no existe, descarga el instalador de docker.com/products/docker-desktop y ejecútalo (marca «Use WSL 2 instead of Hyper-V»).

Cierra sesión o reinicia. Abre Docker Desktop, acepta los términos (puedes omitir crear cuenta) y en Settings → General deja activado:

  • «Start Docker Desktop when you sign in to your computer»
  • «Use the WSL 2 based engine»

Comprueba en PowerShell (normal):

docker --version
docker compose version
docker run --rm hello-world

El último debe mostrar «Hello from Docker!».

3Copiar el sistema

Copia FARMACONTROL_instalacion.zip a la PC y descomprímelo en C:\ (clic derecho → Extraer todo…). Debe quedar C:\FARMACONTROL\. O en PowerShell:

Expand-Archive -Path "$env:USERPROFILE\Downloads\FARMACONTROL_instalacion.zip" -DestinationPath C:\ -Force
No lo pongas en el Escritorio ni en OneDrive: la sincronización puede bloquear archivos.

4Instalar y arrancar

Con Docker Desktop abierto («Engine running»), entra a C:\FARMACONTROL y da doble clic en 1_INSTALAR.bat. La primera vez tarda de 5 a 15 minutos (descarga y construye las 3 imágenes: base de datos, sistema y API). Al terminar se abre el navegador en http://localhost:5010.

Equivalente manual en PowerShell:

cd C:\FARMACONTROL
docker compose up -d --build
docker compose ps

Los tres servicios deben decir running / healthy.

5Abrir el acceso a la red

  1. Doble clic en 2_ABRIR_FIREWALL.bat (pide permiso de administrador). Abre los puertos 5010 y 8000.
  2. Configuración → Red e Internet → Propiedades de tu red → perfil Privada.
  3. Doble clic en VER_DIRECCION.bat: muestra la dirección para los demás, por ejemplo http://192.168.100.91:5010.
  4. En el módem/router reserva esa IP para esta PC (opción «Reserva DHCP» o «IP fija») para que no cambie.
  5. Opcional: en el archivo .env cambia API_PUBLIC_URL=http://localhost:8000 por http://TU-IP:8000 y vuelve a ejecutar 1_INSTALAR.bat (así el botón de Swagger funciona desde otros equipos).

Comando equivalente del firewall (PowerShell administrador):

New-NetFirewallRule -DisplayName "FarmaControl" -Direction Inbound -Protocol TCP -LocalPort 5010,8000 -Action Allow -Profile Private,Domain

6Primer uso

  1. Entra con admin / 131004131004 y cámbiale la contraseña en Usuarios.
  2. Crea los usuarios: farmacéuticos con rol Farmacéutico; doctores con rol Administrador (el módulo clínico es solo para ese rol).
  3. En Clínica → Perfil médico captura nombre, cédula, universidad, teléfono, WhatsApp y logos de la receta.
  4. Prueba una venta con los productos de prueba y una consulta con un paciente de prueba.
  5. Cuando todo funcione: elimina los 3 productos de prueba (Inventario) y da de baja los 2 pacientes (Clínica → Pacientes).
  6. Para que las recetas sigan tu numeración (ej. la última fue 1541), en PowerShell dentro de C:\FARMACONTROL: 
    docker compose exec db sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD medicalife -e "ALTER TABLE recetas AUTO_INCREMENT = 1542"'

7Que siempre esté encendido

Los contenedores se reinician solos cuando Docker arranca. Para que la PC no se duerma (PowerShell administrador):

powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
powercfg /change monitor-timeout-ac 15

Docker Desktop arranca al iniciar sesión: deja la sesión de Windows iniciada (o configura inicio de sesión automático con netplwiz).

8Impresora de tickets

  1. Instala el controlador del fabricante de la impresora térmica (modelo exacto: POS-80, Epson TM-T20, Xprinter…). No uses un controlador genérico, o imprimirá códigos raros.
  2. En sus preferencias elige papel de 80 mm.
  3. Al imprimir desde Chrome/Edge: Márgenes «Ninguno», desactiva «Encabezados y pies de página».

Cada computadora imprime en su propia impresora: instálala en la PC de caja que la tenga conectada.

9Uso diario y respaldos

ArchivoPara qué
INICIAR.batEnciende el sistema (normalmente arranca solo).
DETENER.batApaga el sistema. Los datos se conservan.
ESTADO.batMuestra si todo está funcionando y los últimos mensajes.
RESPALDO.batGuarda la base de datos en respaldos\respaldo_FECHA.sql. Hazlo al menos una vez por semana y copia el archivo a una USB o a la nube.
VER_DIRECCION.batMuestra la dirección para los demás equipos.

Restaurar un respaldo (PowerShell en C:\FARMACONTROL, cambia el nombre del archivo):

docker compose cp .\respaldos\respaldo_20261006_1800.sql db:/tmp/r.sql
docker compose exec db sh -c 'mysql -uroot -p$MYSQL_ROOT_PASSWORD medicalife < /tmp/r.sql'

Actualizar el sistema más adelante: reemplaza los archivos del programa (sin borrar .env ni respaldos) y ejecuta 1_INSTALAR.bat. Los datos no se pierden.

Nunca ejecutes docker compose down -v: la opción -v borra la base de datos.

?Problemas comunes

SíntomaSolución
«WSL 2 installation is incomplete» / Docker no arrancaPowerShell administrador: wsl --update y reinicia.
«Virtualization support not detected»Activar virtualización en la BIOS (paso 0).
Funciona en la PC pero no en otros equiposEjecuta 2_ABRIR_FIREWALL.bat, red en «Privada», mismo Wi-Fi (no red de invitados) y usa la IP de VER_DIRECCION.bat.
«port is already allocated»Otro programa usa el 5010: cambia WEB_PORT=5011 en .env y vuelve a instalar.
La página no carga justo después de encenderEspera 1 minuto: la base de datos tarda en arrancar. Revisa con ESTADO.bat.

El archivo .env trae claves únicas generadas para esta instalación. Guarda una copia en lugar seguro.
